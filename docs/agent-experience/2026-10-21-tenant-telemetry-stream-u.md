## 2026-10-21 — tenant isolation stream: integration health, PageView/EmailLog orgId (#1555 → #3070, #1556)

- **An issue's "current state" can be months stale. Check every acceptance item against main before writing code.** #1555 was already done by #2357, apart from one reader. The remaining leak turned up only when I grepped *every* `prisma.webhook.` call site, not just the routes the issue named: `src/lib/integrationHealth.ts` counted every tenant's webhooks, audit drains and SSO configs.
- **Registering a model in `TENANT_MODELS` changes the deletes that run inside a tenant scope, too.** `forgetEmailLog()` runs inside `withTenantScope` (the admin erase route). Once `EmailLog` was registered, its `deleteMany({ to })` would have been narrowed to the admin's org, and NULL-org legacy rows would silently survive an erasure. Wrap such deletes in `runUnscoped` (`src/lib/tenantAmbient.ts`). For mail rows, write the *recipient's* org explicitly, null included, so the middleware never stamps the sender's scope.
- **The backfill registry's run order is the array order, not the id number** (`prisma/backfills/registry.mjs`). A new attribution backfill that must run before `0011-organization` takes the next free number and its place in the list. Renumbering would re-run the `once` grandfather entries.
- **In a fresh git worktree, run `npm ci` before any `npx`.** Without `node_modules`, `npx prisma format` silently downloads prisma 8 rc and runs it against the schema.
- **Playwright 1.64 wants `chromium-1248`, but the container ships 1194.** Symlink `chromium-1248 → chromium-1194`. Then create `chromium_headless_shell-1248/chrome-headless-shell-linux64/` holding per-file links to `chromium_headless_shell-1194/chrome-linux/*`, plus `chrome-headless-shell → headless_shell`. Never run `playwright install`.
- **After a container restart MySQL can refuse to start: "Another process … is using unix socket file".** `rm -f /var/run/mysqld/*.lock && service mysql start`.
- **Under `next dev` the first hit on a heavy route can outlast a spec's 10s `toPass`.** `candidate-erasure` and `admin-user-erase` failed on the first iteration and passed on `--repeat-each=2`. CI runs against a production build, so read it as a cold-compile timing issue before calling it a regression.
