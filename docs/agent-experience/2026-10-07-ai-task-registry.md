## 2026-10-07 — AI task registry, one provider module, cost rows (#2022)

- **An `as const satisfies Record<string, Spec>` registry loses its optional fields at the lookup.** `AI_TASKS[id].legacyModelEnv` fails `tsc` with "property does not exist on type … | 7 more", because the union of literal entries only has the keys every entry spells out. Annotate the lookup (`const spec: AiTaskSpec = AI_TASKS[id]`) instead of adding the optional key to every entry.
- **A `const x = y` alias is not a drop-in for a function whose callers `deepEqual` its result.** Aliasing `trackParseErrors = trackAiCall` added a `usage` key to the returned object, and `scripts/test/ai-provider.test.mjs` compares the whole shape. Keep the deprecated name a thin wrapper that returns exactly the old keys.
- **`node --test` with two files reports one combined tally; run the red file alone to see whose test it is.** The 17-test run with one failure was 12 new + 5 old; the failure sat in the old file.
- **Centralising an input cap moves where it bites.** Modules sliced the *text* to 24 000 chars and then wrapped it in a prefix; `callModel()` caps the whole user message. For the open-text engines the rows are already bounded upstream (`MAX_SUMMARY_INPUT_CHARS`), and a central cap at the same number would cut the last row and fail its verbatim quote check — give such tasks a cap above the upstream bound and say why in the registry.
- **`npx prisma validate` needs `DATABASE_URL` set even to validate.** Export a dummy URL for the schema checks, and the real local one for `db push`.
- **`apt-get install mariadb-server` fails with "unable to locate package" until `apt-get update` has run** in this container (the playbook says so; the first attempt skipped it). `service mariadb start` works; `invoke-rc.d` noise during the install is harmless.
- **`npm install` here rewrites `package-lock.json`** (drops `libc` entries, npm version difference); `git checkout -- package-lock.json` before committing.
- **Playwright 1.63 wants `chromium_headless_shell-1243`, the container ships 1194 — and the inner layout changed too.** A directory symlink is not enough: 1194 keeps the binary at `chrome-linux/headless_shell`, 1.63 looks for `chrome-headless-shell-linux64/chrome-headless-shell` (and `chrome-linux64/chrome` for full Chromium). Create the 1243 directories, symlink every file of `chrome-linux/` into the new folder name, add a `chrome-headless-shell` link to `headless_shell`, and `touch INSTALLATION_COMPLETE`. `browserType.launch: Executable doesn't exist` at 2 ms per test is this, not the app.
