# 2026-10-23 — Affiliate module: nav, engine, role, admin screens, portal, migration (#3111, #3113–#3119, #3121/#3122/#3167–#3171)

- **Stacked PRs + squash merges produce add/add conflicts on every next branch.** After #3107/#3120 were squash-merged, merging `origin/main` into the next branch conflicted on files that were byte-identical to our earlier commits. Before taking our side, verify it: `git diff <our-earlier-commit> origin/main -- <file>` must be empty, then `git checkout --ours <file>`. In `src/i18n/dictionaries.ts` the conflict had an empty "theirs" side, so only the markers had to go. Merge (never rebase) into branches that are already pushed.
- **A PR environment that answers 200 can still be a white page.** `curl -sI` said 200 while the body was empty, because the self-hosted deploy queue was stuck. Check the body size or a known string (`curl -s … | wc -c`, `grep`) before you say "the env is up". Check the topic-preview runs too: queued for hours = runner, not code.
- **Playwright reuses a dev server already running on :3000.** That server has no `MARKETING_HOSTS`, so marketing-world specs fail for no reason. Either stop it, or point the specs at it with `E2E_MARKETING_HOST=marketing.localhost BASE_URL=http://localhost:3000 npx playwright test …`. Locally the marketing world is `http://marketing.localhost:3000`, and the port is required: without it the browser says "not reachable".
- **A stale local DB breaks `db push` on unrelated columns.** For example, `Setting.programId` was missing. Run the deploy's expand scripts first, take a `mysqldump`, then run `db push --accept-data-loss`. Ask before you delete local rows that block a new enum value: three old local `AFFILIATE` users had to go.
- **`prisma format` reflows the whole `Organization` block when a long relation name is added.** That makes a noisy diff. Keep relation field names short, or rebuild the edit from `HEAD` so the diff touches only the new lines.
- **Money is one writer with a row lock first.** Every commission write takes `SELECT … FOR UPDATE` on the partner row, then reconciles: rows that are PENDING on the current plan version are recomputed, and APPROVED/PAID/REJECTED rows or rows from an older version are frozen and reported as drift. A plan change stamps `planEffectiveAt`, so nothing pays retroactively. The reviewer agent found real bugs in each of three passes (10, 8 and 9 findings). For money/auth changes, run it before the PR is marked ready, not after.
- **Bulk transitions answer honestly.** `transitionCommissions` uses one transaction per partner and returns `{ moved, skipped, failedPartners }`, never all-or-nothing across partners. A payout is all-or-nothing on its own rows (`payout_mismatch`). A plan save that worked but whose re-evaluation failed for a partner reports `resyncFailed`, not an error.
- **Two local checks are false alarms.** The `hardcoded-strings` check flags a literal `?ref=` in JSX, so build it with a template expression. `fillTemplate()` returns a ReactNode; for an attribute or a plain string use `interpolate` from `src/lib/notificationText`. The `gitignore-exports` unit test fails only on macOS (`core.ignorecase`), so it is not a regression.
- **Issue and PR numbers are one sequence.** A busy repo can skip 40+ numbers between two of your PRs (#3122 → #3167). Nothing is lost; the gap is other people's issues, PRs and bots.
- **`runImport` commits chunk by chunk.** A migration that must reconcile as a whole cannot run that way. Set `chunkSize: Number.MAX_SAFE_INTEGER` and write everything in one transaction in `apply`, then re-check the totals against the rows actually written before commit. The engine never calls `apply` for a table with zero rows, so a set with only partners needs its own write path after the call.
- **`parseMinorUnits` guesses, and both sides of a reconciliation guess the same way.** It strips every character that is not a digit, `.`, `,` or `-`, and treats any tail of 3+ digits as a thousands group. So `100.0000` became €1,000,000, `1e3` became €13 and `−5` (U+2212) became +€5. Because the same file feeds both sides, the totals still matched. Money that comes from a file needs a strict shape check first (`parseMigrationAmount`).
- **Match keys to the DB collation, not to `toLowerCase()`.** `utf8mb4_unicode_ci` treats accents and `ß`/`ss` as equal. A rule that only lowercases passes `Müller`/`Muller` in the dry run, and the real run then hits P2002. Normalize with NFD, strip marks, map `ß`→`ss`. Classify a P2002 by checking what is actually in the DB, not by assuming.
- **`File.text()` silently turns a Windows-1252 CSV into U+FFFD.** Different names then collapse into one customer. Decode with `new TextDecoder('utf-8', { fatal: true })` and refuse cells that contain `\uFFFD` on the server too.
- **A "check again inside the transaction" is not a lock.** Under REPEATABLE READ a count is a snapshot. Two disjoint migrations can both see an empty programme. Take `SELECT … FOR UPDATE` on the organisation row, and have every competing writer (`createPartner`) take the same lock.
- **Under `/admin`, a gated page answers 200, not 404.** `src/app/admin/loading.tsx` streams the response, so the status line is already sent when `notFound()` runs; the 404 shows up only as `NEXT_HTTP_ERROR_FALLBACK;404` in the body. Assert that marker, and add a control proving the same page renders where it should, or the check passes for nothing. Routes without a `loading.tsx` (`/affiliate`) still give a real 404.
- **Read the route list for a boundary sweep from the file system.** Walk `src/app/api/...` for `route.ts`, take the methods from `export async function (GET|POST|…)`, and add a floor on the count. New routes are covered without anyone editing the test, and the floor fails if a folder moves.
- **Opening the generic invitation board to a new role is a privilege change.** `POST /api/invite/[id]` resends to any ADMIN tier and returns the live register link. That was harmless while AFFILIATE tokens created nothing. Once they did, an OBSERVER could open a partner's account and set its IBAN. When a role starts creating accounts, check every older route that hands out its tokens.
- **Run one reviewer pass over the whole module after the per-step passes.** It found what no single step could: a migrated `ended_on` silently dropped, a terminated partner still gaining new customers, and N+1 queries that only hurt after a 5,000-partner migration. Hand it `main...HEAD` and ask only for interaction findings.
