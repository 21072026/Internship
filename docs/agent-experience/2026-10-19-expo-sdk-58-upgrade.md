## 2026-10-19 — the mobile app's Expo SDK 57 → 58 upgrade (#2976, #2775)

- **`npx expo install --fix` writes `package.json` and then fails `npm install` with `ERESOLVE … Conflicting peer dependency: @expo/ui@58`.** The old lockfile still holds expo-router 57's `@expo/ui` 57, and npm will not move it for expo-router 58's optional peer `@expo/ui ^58`. Deleting `node_modules` alone does not help; delete `apps/mobile/package-lock.json` as well, `npm install`, then run `npx expo install --fix` once more (it caught `@types/react` only on the second pass). Check the result with `npx expo install --check` and a clean `npm ci`.
- **expo-router has no CHANGELOG in its npm tarball; expo-notifications does.** Read the router's from `https://raw.githubusercontent.com/expo/expo/sdk-58/packages/expo-router/CHANGELOG.md` with `curl`, which gives the raw file rather than a summary.
- **react-native-webview 14 changed `WebView<P = {}>` to `WebView<P = undefined>`.** Its props are `WebViewProps & P`, so `useRef<WebView>(null)` makes the props `never`, and `tsc` reports every prop on the element as "not assignable to type 'never'". The real cause is the ref; type it `useRef<WebView<object>>(null)`.
- **React Native 0.88's `ColorValue` is `null | string | number | NativeColorValue`.** A tab bar's `tabBarIcon` hands an icon that type, and `@expo/vector-icons` 15 accepts only `string | OpaqueColorValue`. FlatList's `ListHeaderComponent` no longer takes `null`; pass `undefined`.
- **To find which prop breaks a JSX overload, bisect in a throwaway file.** Put one `<Component … />` per prop in `src/__probe/probe.tsx`, run `npx tsc --noEmit | grep probe`, then delete the folder. The full error lists every prop as failing and hides the one that does.
- **`npx expo-doctor` flags `expo-font` as a missing peer of `@expo/vector-icons`.** It did so on SDK 57 as well (`expo` depends on `expo-font`, which autolinking resolves), so it is not an upgrade regression.
