## 2026-10-08 — per-feature AI switches, the org kill switch and the policy chain (#2032)

- **A dictionary edit anchored on "the `},` before the next block" lands in the wrong block in another locale.** The EN, TR and DE dictionaries do not keep the same block order, so `rfind('\n  },\n', 0, nextHeader)` put the TR/DE console keys into `migration` and `check:i18n` reported `[de] extra key: migration.taskOn`. Anchor on the block's own header line (`\n  adminAi: {\n`, which occurs exactly three times, EN/TR/DE in file order) and insert right after it — key order inside a block is free.
- **A per-namespace key named `disabled` collides.** Several dictionary blocks already carry a `disabled:` string (a button state), and the duplicate-property error surfaces only in `tsc`, not in `check:i18n`. Name the new copy by what it says (`aiOff`) in the component namespaces, and keep the reason-code name (`disabled`) only inside the maps that are keyed by the gate's reason (`reasons`, `aiReasons`, `aiUnavailable_<reason>`).
- **Adding a member to `AiDenialReason` is a repo-wide search, not a gate change.** Six routes map reasons by hand (`not_configured ? 501 : quota_exceeded ? 429 : 503`), two fold everything into `'unavailable'`, and eight components pick their copy by `body.code`; the compiler catches none of the string ternaries. `grep -rln "quota_exceeded" src` is the list to walk, and the practice-interview routes needed a shared `practiceUnavailable()` before they could say anything new.
- **`Promise.all` destructuring is positional — inserting a call in the middle shifts every name after it.** `const [quota, flaggedCalls, policy] = await Promise.all([getAiQuota(), loadAiPolicy(), count()])` gave `flaggedCalls` the policy object; `tsc` said "Property 'tasks' does not exist on type 'number'". Append new calls at the end of the array.
- **`TranslationFill` read `res.json()` twice** — the second read throws (body already consumed), the `catch` yields `{}`, and the locked copy could never show. Reading the body once above the `if (!res.ok)` and branching on it is the whole fix; the same pattern is worth a glance in any component that reports a `code`.
