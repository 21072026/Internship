## 2026-10-07 — session agenda data model, resolver and trilingual seeder (#1841)

- **Split a resolver into a Prisma-free `*Rule.ts` and a thin `*.ts` that re-exports it.** `src/lib/agendas.ts` needs `prisma` for `instantiateAgenda()`, but `node --test` cannot load a module that imports the Prisma client, and a client component must not pull it into a bundle. `agendasRule.ts` holds the pure helpers; `agendas.ts` does `export { … } from './agendasRule'` and adds the DB function. Do not re-export a name you also import for local use in the same file — `tsc` reports it as a duplicate identifier.
- **Back-relations are the part of an additive model that touches other models.** Four new models meant four extra lines elsewhere (`Organization.agendaTemplates`, `User.agendaTemplates @relation("AgendaTemplateAuthor")`, `MentorshipRelation.sessionAgendas`, `Meeting.agenda SessionAgenda?`). Anchor the `python` replace on the model's last relation line *plus* the blank line and first `@@index` after it — the `}` alone matched a different model's end.
- **A new model with `orgId` fails `check:tenant-models` until it is in `TENANT_MODELS`; a child without `orgId` passes silently** — so the "reached through a scoped parent" comment on the child is the only thing that tells the next reader it was deliberate. Copy MeetingGuest's wording.
- **The seeder's dedupe key is the canonical column, so pick the language of the canonical column once.** `seed-goal-templates` keys on the Turkish title for historical reasons; the agenda library keys on English (`title`/`prompt` = `.en`). Say which in the file header, because an admin renaming that one language's text "renames the row" and the seeder will re-insert the original.
- **A unique `meetingId?` plus `onDelete: SetNull` on both optional parents is what lets an agenda exist before the meeting and survive a retired template.** `prisma format` accepts it; MySQL allows many NULLs under the unique index.
