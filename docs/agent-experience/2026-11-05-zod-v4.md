## 2026-11-05 — zod 3 → 4 migration (#3558, #3564); affiliate + Dependabot PR sweep

- **Pin user-visible wording by measuring it against the old library, not by remembering it.**
  zod 4 still ships zod 3 as `zod/v3`, so `scripts/test/zod-v3-messages.test.mjs` builds every
  schema with both and asserts equal `{ path, message }` pairs. A hand-typed expected string would
  have passed while being wrong (`"Invalid email"` vs `"Invalid email address"`). Use the same trick
  for any library that bundles its previous major.
- **zod 4 reads its error map from `globalThis`, so install it once per runtime:**
  `src/instrumentation.ts` (server) and `src/app/providers.tsx` (browser) call
  `installZodV3Messages()`. A schema-level message (`{ error: '…' }`, `.min(1, '…')`) still wins.
- **`.default()` now fires inside `.partial()` / `.optional()`.** A PATCH schema derived with
  `.partial()` from a create schema with defaults silently resets fields the client did not send.
  Grep `\.default(` and check every schema that is later `.partial()`ed (`requisitionPatchSchema`).
- **`z.record(z.enum(...), v)` became exhaustive** — the zod 3 meaning is `z.partialRecord`.
  `z.record` needs two arguments; refined objects lose `.innerType()` (split the shape out first).
- **`z.coerce.*` input type is `unknown`**, so react-hook-form needs
  `useForm<z.input<S>, unknown, z.output<S>>` with `@hookform/resolvers` ≥ 5 — upgrade both together.
- **Introspection moved to `schema._zod.def`** (`type`, `checks`, `entries`, `element`). Code that
  walked `_def.typeName` (`src/lib/events/payloadSchema.ts`) must keep its output byte-identical;
  the webhook fixture caught it.
- **Never merge on the MCP tool while the `Playwright smoke` aggregator is still queued.** The tool
  can bypass protection; confirm the aggregator's check run is `completed/success` first.
- **Local e2e in this container:** apt MariaDB works; when Playwright wants a newer chromium build
  than `/opt/pw-browsers` has, symlink the directory instead of `playwright install`.
