## 2026-10-27 — the scheduled full suite red for a week (#3059)

- **Read the job logs with `gh api repos/<owner>/<repo>/actions/jobs/<id>/logs > file`, not the MCP
  log tool.** Three 3000-line shard logs into the scratchpad, then
  `sed 's/^[0-9TZ:.-]* //' | grep -nE '^\s+[0-9]+\) \['` lists every failure with its line. The
  issue body names only the tests that failed *after retries*; the shard log also lists the
  "flaky" ones, and two of those had real causes.
- **A landing page reached by a redirect needs the streamed-Suspense wait too.** `gotoSettled()`
  waits out the `<div hidden id="S:0">` copy, but `signInAndSettle()` and every hand-rolled
  sign-in land on `/portal` by a redirect and never did. Three portal specs threw
  `resolved to 2 elements` on their first testid query. `signInAndSettle()` now calls
  `settleStreamedSuspense()`; a spec with its own sign-in helper has to call it after `waitForURL`.
- **Module state is shared by every spec file a worker runs.** `retention-registry.unit.spec.ts`
  cleared the retention registry in `afterAll`, so `safeguarding.spec.ts` found no entries when it
  ran next in the same worker, and passed on retry in a fresh worker. A unit spec that clears a
  registry must put back what it found.
- **`opengraph-image.tsx` injects its card into the segment's metadata whatever
  `generateMetadata()` returns.** The `<head>` looked right, but the RSC payload in the same HTML
  still carried `/for-companies/opengraph-image?<hash>`. When a card must not be advertised in some
  cases, make it a route handler (`opengraph-image/route.ts`) and name it from `pageMetadata()`.
- **Check a privacy floor's edge case: a hidden bucket with zero responses.** `applyResponseFloor()`
  hid the smallest shown bucket while the hidden ones summed to under the floor, and that included
  a sum of 0. Nothing can be recovered by subtracting zero answers, so the loop now runs only while
  `0 < hiddenTotal < floor`.
- **`pkill -f "next start"` inside a Bash call kills that call too**, because its own command line
  matches. Find the PID with `ss -ltnp | grep 3000` and `kill` it.
- **Local reproduction works with a production build**: apt MariaDB, `npx prisma db push`,
  `npm run build`, then `CI=1 npx playwright test <spec>` (`CI=1` makes the config use
  `npm run start`). The build takes about 10 minutes in this container, and most of that is the
  type check.
