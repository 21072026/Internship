# 2026-10-31 — Programme eligibility for mentors (#3423)

- **Adding a target to a rule set: decide what "no rule for this side" means.**
  RULES mode admits only on an ALLOW, so evaluating mentors against an empty
  mentor subset would have excluded every mentor the moment a mentee rule set
  went live. Mentors with no applicable rule are `open`; mentees keep #1945's
  meaning exactly.
- **A pool filter is cheapest as an id list in the WHERE**: `loadMentorPool`
  asks `eligibleUserIds(..., 'MENTOR')` first and returns `null` (no extra
  condition) when nobody is excluded, so orgs without mentor rules pay one
  scope query and no profile query.
- `scopes.generated.ts` is gitignored and only regenerated by install/dev/build:
  after merging main, a new `src/app/<dir>` shows up as a TS error in its
  layout until you run `node scripts/i18n-scopes.mjs`.
