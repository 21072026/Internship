## 2026-10-07 — native push for the mobile app through Expo (#2775, #2848)

- **`infra/deploy-prod.sh` and `infra/server/topic-deploy.sh` forward env vars by an explicit `-e` list, not `--env-file`.** A new server variable placed only in `/etc/internship-crm/*.env` never reaches the container, and nothing fails: the code simply sees it unset. Add every new variable to both lists, and to `.env.example`, in the same PR. `EXPO_ACCESS_TOKEN` needed this.
- **One phone holds one Expo push token for both products.** A token-unique table therefore lets a second product's sign-in steal the first product's row. Key per-device rows by `(token, host)` and take the host from the request (`isServedHost` + `hostnameOf`), never from the body.
- **A "refresh on every launch" undoes a server-side revoke unless the refresh is a different verb.** `POST /api/push/native` with `refresh: true` only updates an existing row. The app tracks the token it registered per host in AsyncStorage, and registers (creates) only after a sign-in or when the token changes.
- **Pair new per-device revocation inside `revokeAllTrustedDevices` / `revokeTrustedDevicesForUsers`, not at the call sites.** Seven paths stamp `sessionsValidFrom`, and all of them already call one of those two functions.
- **`prisma generate` in a worktree whose `node_modules` is a symlink to the main checkout writes the other checkout's client.** Clone the folder instead: `cp -cR ../Internship/node_modules node_modules` is an instant APFS copy. Then run `npm ci` if `tsc` reports missing modules (`qrcode`): the main checkout's `node_modules` was stale.
- **`scripts/test/gitignore-exports.test.mjs` fails on macOS** because `core.ignorecase=true` lets `!scripts/fixtures/*.csv` match `.CSV`. It is green on Linux CI. Run locally with `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=core.ignorecase GIT_CONFIG_VALUE_0=false npm run test:unit:coverage`, rather than changing the shared repo config.
- **`apps/mobile`'s tsconfig has no Node types, so `app.config.ts` cannot use `fs` or `__dirname` out of the box.** Add `@types/node@22` as a devDependency plus `/// <reference types="node" />` at the top of the config. The optional `google-services.json` needs `existsSync`, because a `googleServicesFile` that points at a missing file breaks prebuild.
- **`expo-device` is not needed for push, and its usual `Device.isDevice` gate would block the Android emulator.** A Google Play system image does get FCM tokens. It was installed as asked, then removed.
- **Topic envs cannot test the app.** The app's hosts are fixed per `APP_ENV` (production or preview), so `pr<N>.interncrm.com` is unreachable from it, and a push from there carries a host no build recognises. The end-to-end check runs against `preview.interncrm.com` after merge.
- **A new nav key on the web turns `apps/mobile` tests red on main** (`migrate`, #2825), because the mobile CI only runs when `apps/mobile/**` changes. The first mobile PR after such a key carries the missing icon.
- **Another local session can share the e2e database and port 3000.** Playwright's `reuseExistingServer` then runs your specs against the other session's dev server (another branch's code), and that session's `db push --accept-data-loss` drops your new tables. Check `lsof -nP -iTCP:3000 -sTCP:LISTEN` and `pgrep -fl "playwright test"` before trusting a local red run. CI's isolated MySQL per shard is the real verdict.
- **A wait loop that greps a log for `passed|failed` can match an old line.** Examples: a screenshot path `test-failed-1.png`, or the previous run's summary. Two Playwright runs then overlap on one port. Match the summary shape instead, `^\s+[0-9]+ (passed|failed)`, against a fresh log file.
