## 2026-10-13 — native push on the Android emulator: Firebase, EAS credentials, two app bugs (#2775)

- **The Firebase console in the built-in browser can be signed in as several Google accounts.** `/u/0/` was the personal Gmail; the bcsit account was `/u/1/`. Check the account button's label before you create anything. Switching accounts from the avatar menu opens a new tab, which the pane blocks. Navigate to `/u/<n>/` directly rather than putting an e-mail in the URL.
- **On Android, expo-notifications fires `addPushTokenListener` on every token fetch, not only on rotation.** `PushTokenModule.kt` calls `onNewToken` after each `getDevicePushTokenAsync`, which `getExpoPushTokenAsync` uses. A listener that registers the token again therefore loops forever. Dedupe on the token value.
- **Creating the first Android notification channel can show the system permission prompt immediately.** Any explanation you meant to show first is lost. Create the channel after the person agrees, or once permission is already granted.
- **A dev build cannot test a cold-start notification tap.** expo-dev-client's launcher takes the launch intent, and `useLastNotificationResponse` reads `null`. Build the release variant (`npx expo run:android --variant release`, ~25 min on an Intel Mac); it installs over the debug build and keeps the session.
- **`am force-stop` blocks FCM delivery until the app is launched again; `am kill` does not.** Use `am kill` on a backgrounded app to simulate "app closed".
- **To see whether a push reached the device at all, read the GMS log:** `adb shell dumpsys activity service com.google.android.gms/.gcm.GcmService`. It lists `Received <package>` / `Successful broadcast` per message. A Firebase Console test message to the raw FCM token separates Expo problems from FCM problems.
- **An Expo receipt of `ok` does not mean the device got the message.** Right after the FCM V1 key was assigned, sends came back `ok` and never arrived; a few minutes later they did.
- **`eas credentials` run from the repo root creates a NEW EAS project.** It finds no Expo app there, offers `@bcsit-gmbh/internship-crm` and writes a root `app.json`. Always run it inside `apps/mobile`, and check that the summary says Project `interncrm`.
- **`eas env:create` is deprecated in favour of `eas env:set`** (same flags). `eas env:list` has no `--non-interactive` flag.
- **Drive interactive `eas credentials` menus read-only with `expect`.** Send arrow keys and Enter, wait for the next prompt's text, and send Ctrl-C before any choice that writes. That was enough to read the FCM V1 assignment and the account's key list without changing anything.
