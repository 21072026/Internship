## 2026-10-07 — native mobile app: message links, keyboard, local APK builds (#2775)

- **Edge-to-edge Android (Expo 57) makes React Native's `KeyboardAvoidingView` a no-op.** The window is no longer resized, and `behavior={undefined}` did nothing. Use `react-native-keyboard-controller` (`KeyboardProvider` at the root). In a chat screen, a reanimated spacer of `-keyboard.height - insets.bottom` under the composer needs no header-height offset. Confirmed on a device.
- **Catching navigations inside a WebView needs more than one hook.** `onShouldStartLoadWithRequest` only sees full loads. Next `<Link>` and `router.push` are `pushState`, and an RSC `redirect()` (e.g. legacy `/messages/<relationId>`) arrives as **`replaceState`** to the new path. Next also calls `replaceState` on the URL it is already on, so compare against the previous path. Inject the hook with `injectedJavaScriptBeforeContentLoaded`, and stop link taps in a capture-phase listener on `document`. Verify against the real dev server with a throwaway Playwright spec that uses `addInitScript` and a stubbed `window.ReactNativeWebView`.
- **`npx expo install` can re-pin transitive native modules** (reanimated, worklets). After that, Gradle fails with a missing `libworklets.so` from stale `node_modules/*/android/.cxx` and `build` dirs. Delete them (`find node_modules -maxdepth 4 -path "*/android/.cxx" -o -path "*/android/build"`) before rebuilding.
- **Reanimated and worklets were already autolinked through expo-router.** Check `android/build/generated/autolinking/autolinking.json` before assuming a new native dependency grows the APK. The arm64 APK stays at about 27MB with `-Pexpo.useLegacyPackaging=true`, under the 30MB `SendUserFile` limit.
- **Some setup cannot run in the cloud container:** Expo login and `EXPO_TOKEN`, and a local emulator. Queue those as `spawn_task` cards for a *local* session, with self-contained prompts. Never handle the user's passwords or tokens.
