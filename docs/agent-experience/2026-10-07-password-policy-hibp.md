## 2026-10-07 — configurable password policy + HIBP screening (#1544)

- **A rule that both the browser and the server must apply goes into one dependency-free module, and the server module stays server-only.** `src/lib/passwordPolicyRule.ts` has no imports, so the register form's zod `superRefine`, the reset page, the account page and `src/lib/password.ts` all call the same `failedPasswordRules()`. `password.ts` itself now imports Prisma-backed settings, so it must never be imported from a client component again — the forms get the policy from `GET /api/auth/password-policy` instead.
- **A policy resolved per org cannot live in a module-scope zod schema.** `passwordSchema` is now only the shape (non-empty, ≤ 200) and each route calls `await checkPassword(pw, orgId)` after it knows the account's org (register: the invitation's org or the default org; reset: the user the token was minted for; account: the session user's org). Read the three call sites before assuming they share a place to hook in — they did not.
- **A third-party lookup in a sign-up path fails open, and the e2e run never touches the real service.** `e2e/support/hibp-mock.mjs` speaks the range API's wire format on a loopback port; `HIBP_RANGE_URL` + `HIBP_ALLOW_INSECURE_STUB=1` (test-only, logs a warning) let the app reach it past the SSRF guard. The stub records request paths so the spec can assert from the receiver's side that only a 5-character prefix ever arrives. Same pattern as the audit sink (#2012) — reuse it for the next outbound integration.
- **Check which passwords existing specs register with before inventing a "known breached" list.** `grep -rhoE "'[A-Za-z]*Pass[A-Za-z0-9!]*'" e2e/` showed every spec uses `*Pass123` variants; the stub flags only `Password123` / `password` / `123456` / `qwerty`, so no existing registration is refused.
- **Removing an i18n key means removing it from all three locales in the same edit** (`account.passwordHint` went when the dynamic rule list replaced it); `check:i18n` fails on parity, and the MARKETING leak ratchet counts the word "internet" as an internship leak — say "publicly reachable" instead.
- **An admin-settings number input needs the API's range check, not only the zod shape.** `passwordMinLength` is clamped to ≥ 8 on read, so storing `'7'` would silently read back as 8; the route refuses it with `field: 'passwordMinLength'` so the form can say so.
