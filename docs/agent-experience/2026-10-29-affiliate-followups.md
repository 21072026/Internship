# 2026-10-29 — Affiliate follow-ups: referral error, file picker, overview, plan resync on the queue (#3176, #3175, #3173, #3170)

- **Never guess a PR number.** I called `merge_pull_request` in the same batch as `create_pull_request`, guessed the next number, and merged someone else's PR (#3260). Other sessions open PRs every few seconds. The GitHub MCP merge **ignored a mismatched `expectedHeadSha`** and merged anyway, so that guard does not protect you. Create the PR, read the number it returns, then merge in a separate call.
- **The container can be recycled mid-session.** After a long pause MariaDB was gone ("Can't reach database server"), while `node_modules`, the `.env` and the Playwright browser symlinks were still there. `service mariadb start` plus re-creating the `crm` user was enough. The Playwright webServer then waits its full 120 s and fails, so check the DB first.
- **e2e helpers do not read `.env`.** Spec-side Prisma (`e2e/helpers/db`) said "Environment variable not found: DATABASE_URL" until I ran `set -a; . ./.env; set +a` before `npx playwright test`.
- **Cold dev compiles time out the first UI test of a run** (sign-in 15 s, `waitForURL` 20 s), mostly right after a restart. A `--retries=1` run that passes warm tells you it is compile time, not your change. Give a post-click URL assertion that lands on a new route a 60 s timeout.
- **`src/i18n/scopes.generated.ts` goes stale after merging main** when main added top-level `src/app` directories: tsc then fails in `src/app/<new>/layout.tsx`. Run `node scripts/i18n-scopes.mjs` (gitignored, never committed).
- **Pull a slow loop out of a request onto the queue in three parts:** pure state rules (checkpoint cursor, retry list with a cap, statuses), a handler that writes that state only through `updateMany` guarded on a version (so a newer save stops an older job), and the enqueue keyed on `<org>:<version>`. The dev server's worker ticks every 5 s, so e2e can `expect.poll` the state. Call the handler in-process on an org no job was queued for, to test resume and retry deterministically.
- **Prove "a fixed number of queries" in-process.** Give the reader its client as a parameter and wrap Prisma in a `Proxy` that counts delegate calls. Assert the count is the same at 1 and 25 partners. No DB general log needed.
- **A shared file picker:** keep the real `<input type="file">` `sr-only` (never `display:none`), so focus, label and `setInputFiles` keep working. Style its `<label>` as the outline button and draw the ring with `peer-focus-visible`.
