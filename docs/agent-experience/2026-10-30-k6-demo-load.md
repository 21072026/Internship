# 2026-10-30 — authenticated + SSE k6 against the demo (#1612)

- **k6 runs in this container**: `curl -L` the release tarball from GitHub into the scratchpad
  and put it on PATH; then `K6_CHECK_REQUIRED=1 npm run check:k6` really parses `k6/`
  (without the binary it only warns). Subdirectories of `k6/` (e.g. `k6/lib/`) are imported,
  not archived as scripts.
- **k6 cannot read a response incrementally**, so an SSE test needs the server to close the
  stream: the route's `?maxSeconds=` (clamped, can only shorten) plus a server timestamp in
  the heartbeat comment turn "heartbeat drift" into something a plain `http.get` can measure.
- NextAuth credentials sign-in from k6: `GET /api/auth/csrf` (text body) → `POST
  /api/auth/callback/credentials` with `{csrfToken,email,password,json:'true'}` and
  `redirects: 0`; the cookie is `next-auth.session-token` on http, `__Secure-…` on https.
  `discardResponseBodies: true` needs a per-request `responseType: 'text'` where you parse.
- Validate locally with `npm run seed:demo` + `npm run dev` + `K6_ALLOW_LOCAL=1` — and run
  `npx prisma generate` after merging main first: a stale client made `POST /api/messages`
  500 on a column the new schema had renamed.
